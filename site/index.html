The name

Verba volant, scripta manent.

Latin proverb: spoken words fly away, written words remain.

That is the whole idea behind event sourcing. In Scripta, every event is written once and kept forever, and the current state of your domain is simply what those events add up to.

What it looks like

An aggregate is a plain Java class. Events are records behind a sealed interface, so the compiler checks that every event is handled.

Scripta is pre-release, so the API shown here is a design target and may still change.

Principles

  • Zero runtime dependencies

    The core module depends on the JDK and nothing else. Integrations live in separate, optional modules.

  • Plain Java, no magic

    Aggregates and events are ordinary classes, records and sealed types. No reflection tricks, no bytecode generation.

  • Optimistic concurrency

    Every append checks the expected stream version, so conflicting writes fail loudly instead of silently overwriting.

  • Projections you can trust

    Read models track checkpoints and can be rebuilt from the event log whenever their shape changes.

  • Testing first

    Given/when/then fixtures let you test behaviour as events in, events out, without a database.

  • Pluggable storage

    The event store sits behind a small interface. PostgreSQL is the first implementation.
